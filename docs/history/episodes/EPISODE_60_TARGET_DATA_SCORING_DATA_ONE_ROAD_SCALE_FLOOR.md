# Episode 60 — Target Data / Scoring Data / One Road Scale Floor

**Date:** 2026-09-08

**Status:** FOUNDER APPROVED / SCALE MILESTONE LOCKED

## Summary

Episode 60 proved that materially different target structures can run through one shared shooter road when target identity, aim structure, geometry, scoring semantics, and preservation facts are supplied as data.

## Problem

Target growth had repeatedly threatened to become application growth. Scoring logic shaped around individual paper products would make every new target another software project and would erase the economic leverage of SCZN3's shared road.

## Discovery

Capture and preservation were already universal. The remaining boundary was scoring expression. Moving recurring scoring structures behind a governed target-scoring data contract allowed nine diverse targets to change while the road did not.

## Governance decisions

- **Target = data. Scoring = data. Road = software.**
- Printer/P-OS supplies printer-derived target/scoring data.
- UGO supplies the photographed target's spatial relationship.
- Shared software consumes the data.
- No target-specific scoring application is allowed when the shared contract can express the behavior.
- A truly missing behavior is implemented once as the smallest reusable capability.

## Outcome

Nine of nine target roads passed at both 1180px and 390px. No target-specific production implementation and no new shooter road were added. Each session preserved its exact observations and result through SEC, Ballistic Vault, and exact reopen. Production build output was 426 public files.

The milestone changes the economics of SCZN3: more target products can become governed data running through software already paid for. The 2,570-target inventory supplies the scale context, while the proof remains bounded to the nine validated targets.
